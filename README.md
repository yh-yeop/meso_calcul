# 메소 — 장부 · 계산기

메이플스토리 메소를 한곳에서 관리하는 웹서비스. **어디서 벌고 어디에 썼는지 적는 장부**, **목표 메소 도달일 계산기**, 그 둘이 같이 쓰는 **캐릭터별 보스 수익**을 탭 하나씩으로 묶음.

**→ https://yh-yeop.github.io/meso_calcul/**

빌드 없음. 의존성 없음. 서버 없음. `index.html`을 그냥 브라우저로 열어도 동작함(Open API · 오프라인 캐시만 http(s)에서).

| 탭 | 하는 일 |
|---|---|
| 홈 | 현재 잔고 · 이번 달 순수익 · 지출 · 예산, 목표 진행도(실측 페이스 도달일 vs 계산기 계획), **이번 주 보스 체크**, 최근 기록 |
| 장부 | 기록 · 통계 · 예산 (아래 "메소 장부") |
| 계산기 | 목표 메소 도달일 (아래 "기능") |
| 캐릭터 | 보스 도는 캐릭터와 주보 · 월보 수익. 계산기 · 장부 · 홈이 전부 이 값을 씀 |
| ⚙ 설정 | 테마, 넥슨 Open API 키 · 동기화, 통합 백업 · 복원 · CSV, 계산기 초기화 |

### 구조

`index.html`(화면 마크업) + `app.css` + 기능별 스크립트. 전부 `<script src>`라 `file://`에서도 그대로 뜸.

| 파일 | |
|---|---|
| `core.js` | 계산기 순수 로직 `MesoCore` — 달력 시뮬레이션, 도달일, 민감도, 정산표 파서. DOM 안 만짐 |
| `store.js` | 공용 헬퍼 · 캐릭터 저장소 · 변경 알림 · 토스트 · 테마 (`Meso`) |
| `api.js` | 넥슨 Open API 클라이언트 |
| `ledger.js` · `calc.js` · `chars.js` · `home.js` | 탭별 화면 |
| `app.js` | 해시 라우팅(`#home` `#ledger[/stats\|/budget]` `#calc` `#chars` `#settings`), 설정, 백업 |
| `bosses.js` | 보스 결정석 가격표 (주간 24종 · 월간, 난이도별). ⚙에서 덮어쓰기 가능 |
| `rules.js` | Open API 이력에 금액을 붙이는 비용표 |
| `ledger.html` | 예전 장부 주소 → `index.html#ledger` 리다이렉트 |

- 운영 메모: 위 파일을 고치면 `sw.js`의 `VERSION` 문자열을 올려야 함. 안 올리면 방문자가 옛 캐시를 한 번 더 봄.

### 보스 수익 — 캐릭터별 루틴

캐릭터마다 **보스 설정**에서 도는 보스 · 난이도 · 파티 인원을 고르면 주간 · 월간 보스 수익이 결정석 가격으로 계산됨 (파티면 가격 ÷ 인원, 소수점 버림 — 게임 규칙). 주간은 캐릭터당 12마리까지, 월드당 주 90개 판매 제한을 넘으면 캐릭터 탭에 경고. 다른 캐릭터 루틴 복사 가능. 가격표(`bosses.js`, 2026-10-22 기준)는 ⚙ 설정의 **결정석 가격**에서 고칠 수 있어서 패치가 나와도 바로 맞출 수 있음. 루틴을 안 정한 캐릭터는 직접 넣은 주보 · 월보 숫자를 그대로 씀.

### 홈 보스 체크

이번 주 잡은 보스만 체크. 캐릭터 행을 펼치면 루틴 보스마다 체크박스가 있고, 체크한 만큼만 장부에 `주간보스 · 캐릭터` 수입으로 들어감(캐릭터 × 주 = 기록 1건, 메모에 보스 이름). 캐릭터 체크박스는 루틴 전부를 한 번에, 일부만 잡았으면 "부분" 표시. 목요일에 새 주로 리셋, 월간보스는 매월. 체크 상태는 따로 저장하지 않고 장부 기록(`src: "chk:…"`)이 곧 상태라, 장부에서 지우면 체크도 풀림. 장부에 직접 적은 같은 주 보스 기록이 있으면 "직접 기록됨"으로 잠김.

### 캐릭터

- 직접 추가 / Open API로 계정 캐릭터 불러오기(월드 · 직업 · 레벨)
- 본캐 표시 · ↑↓ 순서. 누르면 편집 시트 — 그 캐릭터의 장부 실적(이번 달 수입 · 지출, 전체 순익, 최근 기록)도 같이
- 이름을 바꾸면 장부 기록의 캐릭터 이름도 같이 바뀜

## 왜 평균으로 안 나누나

메소는 매끄럽게 들어오지 않음.

- **주간보스** — 목요일 하루에 한 주치가 통째로 들어옴
- **월간보스** — 매월 1일
- **사냥** — 매일 조금씩

"월수익 ÷ 30" 으로 계산하면 목요일 점프를 놓쳐서 도달일이 며칠씩 어긋남. 그래서 이 계산기는 시작일부터 **하루씩 실제 달력을 돌려서** 요일과 날짜를 판정함. 도달일이 목요일에 걸리면 그 사실을 따로 경고해 줌 — 그 주 보스를 못 돌면 일주일이 통째로 밀리는 자리라서.

| | |
|---|---|
| 보스 수입 | 캐릭터 탭의 보스 루틴 합(결정석 가격). 부캐 늘려도 손계산 불필요 |
| 주보 건너뛸 주 | 다가오는 목요일 8개를 칩으로 보여주고, 누르면 그 주 주간보스가 0. 도달 날짜가 며칠 밀리는지 결과에 표시 |
| 일회성 항목 | 이벤트 보상·아이템 판매처럼 특정 날짜에 한 번 들어오는 돈. 음수로 넣으면 큐브·스타포스 같은 지출 |
| 정기 지출 | 재획비·큐브처럼 매주 목요일 / 매월 1일 나가는 돈. 잔고에서 그날 빠지고 월 평균 수익에서도 차감 |

| 사냥 시간별 시나리오 | 0~6시간을 한 표에서 비교. 월수익 · 도달일수 · 도달 날짜 · 현재 대비 증감 |
| 민감도 | 사냥 +1시간/일이 주간보스 몇 억과 같은지 환산 — 캐릭 추가 vs 사냥 시간 늘리기 판단용 |
| 누적 잔고 그래프 | 금색 = 주보 점프, 분홍 = 월보, 자주색 = 사냥 기울기, 하늘색 = 일회성, 주황 = 지출, 민트 = 목표선. 마우스·터치로 훑으면 날짜·잔고·그날 항목 툴팁 |
| 이미지 저장 | 도달 날짜·월 평균 수익·구성 비율이 담긴 결과 카드를 PNG 로. 모바일은 공유 시트 |

| 저장 · 공유 | 입력값은 localStorage에 자동 저장. `링크 복사`를 누르면 계산기 설정과 캐릭터가 URL에 실려서 다른 기기로 넘어감 |
| 장부에서 가져오기 | 시작 보유 옆 `장부` — 장부 잔고로 시작(마지막 기록일 다음 날부터). 시급 옆 `실측` — 장부 최근 28일 실측 시급 |

## 메소 장부

계산기가 "앞으로 얼마 모이나"라면 장부는 "실제로 어디서 벌고 어디에 썼나". 장부 탭 안에 **기록 · 통계 · 예산**.

| | |
|---|---|
| 빠른 기록 | `+ 기록` → 시트에서 항목 타일 → 금액 → 저장. **최근 기록 다시 넣기**로 반복 기록은 탭 세 번. 날짜(오늘/어제) · 캐릭터는 칩, `저장하고 계속`으로 몰아 넣기. 저장 · 수정 · 삭제 모두 되돌리기 가능. 금액은 `21.5` · `21억 3170만` · `2,131,700,000` 다 읽음 |
| 보스 값으로 채우기 | 주보 · 월보를 고르면 캐릭터 탭의 캐릭터별 금액이 버튼으로 뜸 |
| 잔고 확인 | 실제 보유 메소를 넣으면 장부를 거기에 맞추고, 차이를 **미기록**으로 남김 — 빠뜨린 기록이 얼마인지 보임 |
| 월 지출 예산 | 항목별 · 전체 예산. 오늘까지의 페이스 선을 넘으면 노랑, 예산을 넘으면 빨강 |
| 통계 | 이번 달 / 최근 4주 / 전체 — 어디서 벌었나 · 어디에 썼나 순위, 캐릭터별 수입, 큰 지출 TOP 5 |
| 주차별 | 목요일 리셋 기준 주간 수입 · 지출 · 순익 · 잔고 |
| 계산기와 비교 | 잔고 그래프에 계산기 계획 곡선(계산기와 같은 `MesoCore.simulate`). 최근 28일 실측(시급 · 사냥 시간 · 주보 · 지출 · 순수익) vs 계산기 가정. 지출이 목표 도달을 며칠 미루는지 |
| Open API 동기화 | 넥슨 Open API 키를 넣으면 **잠재능력 · 에디셔널 재설정** 지출을 하루 × 캐릭터 단위로 자동 기록. 금액은 `rules.js` 비용표로 계산한 추정치(≈) |

### Open API 동기화

- 키는 [내 애플리케이션](https://openapi.nexon.com/ko/my-application/)에서 발급. 이력 API는 키 주인 계정의 데이터만 줌.
- 키는 이 기기 `localStorage["meso-ledger-key"]`에만 있음. 백업 JSON · CSV · 공유 링크에 안 실림.
- 같은 날을 다시 동기화하면 그날 기록을 교체함(중복 없음). 직접 고친 API 기록은 `API·고정`이 되어 안 덮어쓰고, 지운 기록은 다시 안 들어옴.
- 파일로 직접 열면(`file://`) API 호출이 막힘 — GitHub Pages 주소나 로컬 서버에서 열 것.
- 비용표(`rules.js`)는 공식 표와 대조 전. 재설정 전후로 잔고 확인을 넣으면 오차가 미기록으로 드러남.
- 설계와 다음 단계(스타포스 · 보스 · 심볼)는 [docs/openapi-design.md](docs/openapi-design.md).

Data based on NEXON Open API.

장부 잔고는 마지막 기록일 마감 기준이라 계산기에서 `장부`로 가져오면 시작일은 **그 다음 날**이 됨 (계산기는 시작일 당일 수익부터 더하므로 겹치지 않게).

## 한 달 = 4.348주

보스 정산 사이트들은 월 합계를 **한 달 = 4주**로 잡는 경우가 많음. 실제로는 365.2425 / 12 / 7 = **4.348주**라서 그런 월 합계는 실제보다 8% 정도 적음. 이 계산기는 주간 수익을 4.348주로 환산함.

## 저장되는 값

브라우저 localStorage 가 원본. ⚙ **계정 · 동기화**에서 Google 로 로그인하면 아래 장부 · 캐릭터 · 계산기 · 결정석 가격이 Firestore 의 내 계정 칸에도 올라가서 다른 기기와 맞춰짐(로그인 안 하면 서버로 아무것도 안 감). API 키 · 테마는 기기마다 따로.

- `localStorage["meso-chars-v1"]` — 캐릭터(이름 · 보스 루틴 · 직접 입력 주보/월보 · 본캐 · 월드/직업/레벨). 없으면 예전 계산기 저장값의 로스터(`r`)에서 한 번 옮겨 옴
- `localStorage["meso-boss-prices"]` — ⚙에서 고친 결정석 가격 (`"보스:난이도": 메소`)
- `localStorage["meso-calc-v1"]` — 계산기 입력: 일회성 항목, 정기 지출, 건너뛸 주, 시급 · 기간 · 목표. 옛 저장분도 그대로 읽힘
- `localStorage["meso-ledger-v1"]` — 장부 기록 · 예산 · 동기화 상태
- `localStorage["meso-ledger-key"]` — 넥슨 Open API 키 (장부 백업과 분리)
- `localStorage["meso-theme"]` — 테마 버튼으로 고정한 값(`light`/`dark`). 없으면 시스템 설정
- URL의 `#s=...` — `링크 복사`로 만든 공유 링크(Base64URL): 계산기 입력 + 캐릭터. 열면 한 번 적용하고 주소를 `#calc`로 바꿈
- URL의 `#goal=...` — 목표 메소(억)만 적용하고 주소를 `#calc`로
- `localStorage["meso-sync-base"]` — 마지막으로 클라우드와 맞춘 때의 기록별 해시(3방향 병합 기준), `meso-sync-on` — 다음에 열 때 로그인 이어가기
- 서비스 워커 캐시 `meso-calc-v13` — 화면 · 스크립트 · 아이콘 전부. 열 때마다 뒤에서 새로 받아 갈아끼움

⚙ 백업은 장부 · 계산기 · 캐릭터 · 고친 결정석 가격을 한 JSON 파일로(API 키 제외). 예전 장부 전용 백업도 그대로 복원됨. ⚙ `계산기 초기화`는 계산기 입력만 기본값으로.

## 기기 간 동기화 (Firebase)

로그인 · 저장은 Firebase(Google 로그인 + Firestore, 무료 요금제)가 맡음. 처음 한 번 콘솔에서:

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 만들기 → **웹 앱 추가** → 나오는 `firebaseConfig` 값을 `firebase-config.js`의 `window.MESO_FIREBASE`에 넣기 (공개돼도 되는 값)
2. **Authentication** → 로그인 방법 → **Google** 사용 설정, 설정 → 승인된 도메인에 `yh-yeop.github.io` 추가 (`localhost`는 기본으로 있음)
3. **Firestore Database** 만들기 (위치 `asia-northeast3` 서울)
4. 규칙 게시: `firebase login` 후 `firebase deploy --only firestore:rules` (`firebase.json` · `.firebaserc`가 `meso-save` 프로젝트를 가리킴). 콘솔 규칙 탭에 [`firestore.rules`](firestore.rules)를 붙여넣어도 됨. 규칙을 고칠 때마다 다시 게시

구조: `users/{uid}/meta/state`(캐릭터 · 계산기 · 가격 · 장부 메타 · 연도 목록) + `users/{uid}/ledger/{연도}`(그해 기록). 값은 JSON 문자열 — Firestore 는 배열 안 배열을 못 넣고 문서당 1MB 라 장부를 해마다 나눔. 쓰기는 `rev` 를 확인하는 트랜잭션이라 두 기기가 동시에 써도 하나가 다시 받아 합침.
병합은 기록 단위 3방향(`core.js` `MesoCore.sync`, 테스트 `test/sync.test.js`): 한쪽만 바뀐 건 그쪽, 둘 다 고친 건 이 기기, 양쪽에서 같은 번호로 새로 만든 기록은 둘 다 살림. 처음 연결하는 기기에 데이터가 양쪽 다 있으면 합치기 · 클라우드 것 · 이 기기 것 중에 고름.
