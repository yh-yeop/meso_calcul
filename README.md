# 메소 적립 계산기

메이플스토리 주간보스 · 월간보스 · 재획 수익을 넣으면 목표 메소까지 며칠 걸리는지 계산해 주는 단일 페이지 도구.

**→ https://yh-yeop.github.io/meso_calcul/**

빌드 없음. 의존성 없음. `index.html` 하나가 전부라 파일을 그냥 브라우저로 열어도 똑같이 동작함. (`sw.js`는 오프라인 캐시용으로만 있고, 파일로 열면 안 씀)

## 왜 평균으로 안 나누나

메소는 매끄럽게 들어오지 않음.

- **주간보스** — 목요일 하루에 한 주치가 통째로 들어옴
- **월간보스** — 매월 1일
- **사냥** — 매일 조금씩

"월수익 ÷ 30" 으로 계산하면 목요일 점프를 놓쳐서 도달일이 며칠씩 어긋남. 그래서 이 계산기는 시작일부터 **하루씩 실제 달력을 돌려서** 요일과 날짜를 판정함. 도달일이 목요일에 걸리면 그 사실을 따로 경고해 줌 — 그 주 보스를 못 돌면 일주일이 통째로 밀리는 자리라서.

## 기능

| | |
|---|---|
| 캐릭터 로스터 | 캐릭별 주보/월보를 따로 넣으면 자동 합산. 부캐 늘려도 손계산 불필요 |
| 주보 건너뛸 주 | 다가오는 목요일 8개를 칩으로 보여주고, 누르면 그 주 주간보스가 0. 도달 날짜가 며칠 밀리는지 결과에 표시 |
| 일회성 항목 | 이벤트 보상·아이템 판매처럼 특정 날짜에 한 번 들어오는 돈. 음수로 넣으면 큐브·스타포스 같은 지출 |
| 정기 지출 | 재획비·큐브처럼 매주 목요일 / 매월 1일 나가는 돈. 잔고에서 그날 빠지고 월 평균 수익에서도 차감 |
| 정산표 붙여넣기 | [maplescouter](https://maplescouter.com/ko/boss-income) 페이지 텍스트를 긁어 붙이면 캐릭터별로 자동 분해. 못 찾으면 어떤 단서(#N 블록·라벨·값)를 봤는지 진단 표시 |
| 양방향 계산 | 목표 메소 → 도달일 / 목표 날짜 → 예상 잔고 |
| 사냥 시간별 시나리오 | 0~6시간을 한 표에서 비교. 월수익 · 도달일수 · 도달 날짜 · 현재 대비 증감 |
| 민감도 | 사냥 +1시간/일이 주간보스 몇 억과 같은지 환산 — 캐릭 추가 vs 사냥 시간 늘리기 판단용 |
| 누적 잔고 그래프 | 금색 = 주보 점프, 분홍 = 월보, 자주색 = 사냥 기울기, 하늘색 = 일회성, 주황 = 지출, 민트 = 목표선. 마우스·터치로 훑으면 날짜·잔고·그날 항목 툴팁 |
| 이미지 저장 | 도달 날짜·월 평균 수익·구성 비율이 담긴 결과 카드를 PNG 로. 모바일은 공유 시트 |
| 라이트 테마 | 시스템 설정을 따르고, 헤더의 테마 버튼으로 고정 가능 |
| 오프라인 | 한 번 열면 서비스 워커가 캐시해서 네트워크 없이도 뜸 (GitHub Pages 처럼 http(s)로 열었을 때만) |
| 저장 · 공유 | 입력값은 localStorage에 자동 저장. `링크 복사`를 누르면 설정이 URL에 실려서 다른 기기로 넘어감 |
| 목표만 넘겨받기 | `#goal=781.25` 로 열면 저장된 로스터는 그대로 두고 목표 메소만 바꿈. [어센틱심볼 계산기](https://yh-yeop.github.io/AUTCalcul/)의 결과 링크가 이걸 씀 |

## maplescouter 값과 8% 차이 나는 이유

maplescouter의 월 합계는 **한 달 = 4주**로 잡음. 실제로는 365.2425 / 12 / 7 = **4.348주**라서, 사이트 표시값이 실제보다 8% 정도 적게 나옴.

그래서 이 계산기에는 사이트의 *합계*가 아니라 **주간보스 / 월간보스 원본값**을 넣어야 함. 4.348 환산은 계산기가 함. 차이가 얼마인지는 하단에 표시됨.

## 저장되는 값

전부 브라우저 안에만 있음. 서버로 아무것도 안 감 — 애초에 서버가 없음.

- `localStorage["meso-calc-v1"]` — 로스터, 일회성 항목, 정기 지출, 건너뛸 주, 입력값. 옛 저장분(정기 지출·건너뛸 주 없음)도 그대로 읽힘
- `localStorage["meso-theme"]` — 테마 버튼으로 고정한 값(`light`/`dark`). 없으면 시스템 설정
- URL의 `#s=...` — `링크 복사`로 만든 공유 링크에 담기는 스냅샷 (Base64URL). 위 저장분과 같은 내용
- URL의 `#goal=...` — 목표 메소(억)만 적용하고 주소에서 지움
- 서비스 워커 캐시 `meso-calc-v1` — `index.html`·`icon.svg`·`manifest.json`. 열 때마다 뒤에서 새로 받아 갈아끼움

`초기화` 버튼을 누르면 저장분을 지우고 기본값으로 돌아감 (테마와 오프라인 캐시는 그대로).

## GitHub Pages 배포

Settings → Pages → Source를 **Deploy from a branch**, 브랜치 `main` / 폴더 `/ (root)` 로 두면 끝. 워크플로 파일 필요 없음.

`main`에 푸시할 때마다 1~2분 뒤 반영됨. `.nojekyll`이 있어서 Jekyll 전처리는 건너뜀.

## 로컬에서

```
git clone https://github.com/yh-yeop/meso_calcul.git
```

`index.html`을 브라우저로 열면 됨. 서버 불필요. 서비스 워커만 `file://`에서 안 돌 뿐 나머지는 똑같음.

## 테스트

계산 로직은 `index.html` 안의 `<script id="meso-core">` 블록에 모여 있고 DOM을 건드리지 않음. `test/core.test.js`가 그 블록을 그대로 꺼내 Node에서 돌림 — 파일 하나라는 구조를 깨지 않으면서 달력 시뮬레이션·파서·민감도 계산을 검사함.

```
npm test        # Node 22+, 의존성 없음
```

푸시할 때마다 GitHub Actions가 같은 테스트를 돌림. 앞으로 할 일은 [ROADMAP.md](ROADMAP.md)에.
