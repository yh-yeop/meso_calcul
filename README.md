# 메소 적립 계산기

메이플스토리 주간보스 · 월간보스 · 재획 수익을 넣으면 목표 메소까지 며칠 걸리는지 계산해 주는 단일 페이지 도구.

**→ https://yh-yeop.github.io/meso_calcul/**

빌드 없음. 의존성 없음. `index.html` 하나가 전부라 파일을 그냥 브라우저로 열어도 똑같이 동작함.

## 왜 평균으로 안 나누나

메소는 매끄럽게 들어오지 않음.

- **주간보스** — 목요일 하루에 한 주치가 통째로 들어옴
- **월간보스** — 매월 1일
- **사냥** — 매일 조금씩

"월수익 ÷ 30" 으로 계산하면 목요일 점프를 놓쳐서 도달일이 며칠씩 어긋남. 그래서 이 계산기는 시작일부터 **하루씩 실제 달력을 돌려서** 요일과 날짜를 판정함. 도달일이 목요일에 걸리면 그 사실을 따로 경고해 줌 — 그 주 보스를 못 돌면 일주일이 통째로 밀리는 자리라서.

## 기능

| | |
|---|---|
| 캐릭터 로스터 | 캐릭별 주보/월보를 따로 넣으면 자동 합산. 부캐 늘려도 손계산 불필요 |
| 정산표 붙여넣기 | [maplescouter](https://maplescouter.com/ko/boss-income) 페이지 텍스트를 긁어 붙이면 캐릭터별로 자동 분해 |
| 양방향 계산 | 목표 메소 → 도달일 / 목표 날짜 → 예상 잔고 |
| 사냥 시간별 시나리오 | 0~6시간을 한 표에서 비교. 월수익 · 도달일수 · 도달 날짜 · 현재 대비 증감 |
| 민감도 | 사냥 +1시간/일이 주간보스 몇 억과 같은지 환산 — 캐릭 추가 vs 사냥 시간 늘리기 판단용 |
| 누적 잔고 그래프 | 금색 = 주보 점프, 분홍 = 월보, 자주색 = 사냥 기울기, 민트 = 목표선 |
| 저장 · 공유 | 입력값은 localStorage에 자동 저장. `링크 복사`를 누르면 설정이 URL에 실려서 다른 기기로 넘어감 |

## 메소 장부 (`ledger.html`)

**→ https://yh-yeop.github.io/meso_calcul/ledger.html**

계산기가 "앞으로 얼마 모이나"라면 장부는 "실제로 어디서 벌고 어디에 썼나". 같은 출처라 두 페이지가 서로의 저장값을 읽음.

| | |
|---|---|
| 빠른 기록 | 수입(주보 · 월보 · 사냥 · 판매) / 지출(스타포스 · 잠재능력 · 구매 · 심볼) 칩 선택 → 금액. `21.5` · `21억 3170만` · `2,131,700,000` 다 읽음 |
| 계산기 값으로 채우기 | 주보 · 월보를 고르면 계산기 로스터의 캐릭터별 금액이 버튼으로 뜸 |
| 잔고 확인 | 실제 보유 메소를 넣으면 장부를 거기에 맞추고, 차이를 **미기록**으로 남김 — 빠뜨린 기록이 얼마인지 보임 |
| 월 지출 예산 | 항목별 · 전체 예산. 오늘까지의 페이스 선을 넘으면 노랑, 예산을 넘으면 빨강 |
| 통계 | 이번 달 / 최근 4주 / 전체 — 어디서 벌었나 · 어디에 썼나 순위, 캐릭터별 수입, 큰 지출 TOP 5 |
| 주차별 | 목요일 리셋 기준 주간 수입 · 지출 · 순익 · 잔고 |
| 계산기와 비교 | 최근 28일 실측(시급 · 사냥 시간 · 주보 · 지출 · 순수익) vs 계산기 가정. 지출이 목표 도달을 며칠 미루는지 |
| 계산기에 반영 | 현재 잔고 · 실측 시급 · 실측 사냥 시간을 계산기에 넣고 열기. 계산기 쪽에도 `장부` · `실측` 버튼이 생김 |
| 백업 | JSON 백업 / 복원, 엑셀용 CSV |
| Open API 동기화 | 넥슨 Open API 키를 넣으면 **잠재능력 · 에디셔널 재설정** 지출을 하루 × 캐릭터 단위로 자동 기록. 금액은 `rules.js` 비용표로 계산한 추정치(≈) |

### Open API 동기화

- 키는 [내 애플리케이션](https://openapi.nexon.com/ko/my-application/)에서 발급. 이력 API는 키 주인 계정의 데이터만 줌.
- 키는 이 기기 `localStorage["meso-ledger-key"]`에만 있음. 백업 JSON · CSV · 계산기 연동에 안 실림.
- 같은 날을 다시 동기화하면 그날 기록을 교체함(중복 없음). 직접 고친 API 기록은 `API·고정`이 되어 안 덮어쓰고, 지운 기록은 다시 안 들어옴.
- 파일로 직접 열면(`file://`) API 호출이 막힘 — GitHub Pages 주소나 로컬 서버에서 열 것.
- 비용표(`rules.js`)는 공식 표와 대조 전. 재설정 전후로 잔고 확인을 넣으면 오차가 미기록으로 드러남.
- 설계와 다음 단계(스타포스 · 보스 · 심볼)는 [docs/openapi-design.md](docs/openapi-design.md).

Data based on NEXON Open API.

장부 잔고는 마지막 기록일 마감 기준이라 계산기로 넘길 때 시작일은 **그 다음 날**이 됨 (계산기는 시작일 당일 수익부터 더하므로 겹치지 않게).

## maplescouter 값과 8% 차이 나는 이유

maplescouter의 월 합계는 **한 달 = 4주**로 잡음. 실제로는 365.2425 / 12 / 7 = **4.348주**라서, 사이트 표시값이 실제보다 8% 정도 적게 나옴.

그래서 이 계산기에는 사이트의 *합계*가 아니라 **주간보스 / 월간보스 원본값**을 넣어야 함. 4.348 환산은 계산기가 함. 차이가 얼마인지는 하단에 표시됨.

## 저장되는 값

전부 브라우저 안에만 있음. 서버로 아무것도 안 감 — 애초에 서버가 없음.

- `localStorage["meso-calc-v1"]` — 로스터와 입력값
- `localStorage["meso-ledger-v1"]` — 장부 기록 · 예산 · 동기화 상태, 그리고 계산기가 읽어 가는 요약(`sum`)
- `localStorage["meso-ledger-key"]` — 넥슨 Open API 키 (장부 백업과 분리)
- URL의 `#s=...` — `링크 복사`로 만든 공유 링크에 담기는 스냅샷 (Base64URL)

`초기화` 버튼을 누르면 저장분을 지우고 기본값으로 돌아감.

## GitHub Pages 배포

Settings → Pages → Source를 **Deploy from a branch**, 브랜치 `main` / 폴더 `/ (root)` 로 두면 끝. 워크플로 파일 필요 없음.

`main`에 푸시할 때마다 1~2분 뒤 반영됨. `.nojekyll`이 있어서 Jekyll 전처리는 건너뜀.
